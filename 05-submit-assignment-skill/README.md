# submit-assignment 스킬

> "과제 올려줘" 한마디로, 수업 과제를 GitHub에 규칙대로 올리고 제출 링크까지 받는 Claude Code 스킬

## 왜 만들었나 (불편 → 해결)

과제를 낼 때마다 AI에게 똑같은 설명을 반복했습니다. 같은 말을 하고, 같은 실수를 고치고, 같은 확인을 했습니다.

| 매번 겪던 불편 | 스킬이 해결하는 방법 |
|---|---|
| 레포 주소, 브랜치, 폴더 이름 규칙(`NN-영어이름`)을 매번 다시 설명 | 고정 값으로 스킬에 적어 둠. 묻지 않음 |
| 다음 번호가 몇 번인지 직접 세어 알려줌 | 루트의 `NN-` 폴더 중 가장 큰 번호 + 1을 자동 계산 |
| `.git`, `node_modules`, `.env`가 같이 올라가 폴더가 안 열리거나 키가 노출될 뻔함 | 복사 전에 걸러 내고, 발견하면 알려 줌 |
| 루트 README 과제 목록 표에 한 줄 추가하는 걸 자주 잊음 | 표 갱신을 절차에 포함 |
| 올린 뒤 제출용 링크(소스 / GitHub Pages)를 직접 조립 | 마지막에 링크를 만들어 보고 |
| 코딩 초보라 push 직전이 늘 불안함 | 확인은 push 직전에 딱 한 번. `--force`와 무확인 push는 금지 |

## 이렇게 말하면 발동합니다

- "과제 제출"
- "과제 올려줘"
- "깃허브에 과제 올려"
- "제출 링크 줘"
- "오늘 과제 푸시"

`SKILL.md`의 `description`에 이 문구와 쓰는 상황(끝낸 과제를 올리려 할 때)을 적어 두어, 다른 대화에서도 한마디면 Claude가 스스로 이 스킬을 불러옵니다.

## 동작 순서

1. 올릴 폴더 확인 → 레포 최신화(`git pull`)
2. `NN-영어이름` 폴더 이름 정하기
3. 올리면 안 되는 파일 제외
4. 과제 README 확인, 루트 README 표에 한 줄 추가
5. push 전 확인 한 번 → commit(커밋) & push(푸시)
6. 소스 링크와 실행 링크 보고

## 파일

| 파일 | 역할 |
|---|---|
| [SKILL.md](SKILL.md) | 스킬 본문 (이름·설명·절차) |
| [reference-new-repo.md](reference-new-repo.md) | 과제를 새 레포로 올려야 할 때만 읽는 보조 문서 |

실제로 동작하는 원본은 레포 루트의 [`.claude/skills/submit-assignment/`](../.claude/skills/submit-assignment/SKILL.md)에 있고, 이 폴더에는 같은 내용이 [`.claude/skills/submit-assignment/SKILL.md`](.claude/skills/submit-assignment/SKILL.md)와 위 두 파일로 들어 있습니다.

## 설계할 때 신경 쓴 점

- 자주 쓰는 값(레포·브랜치·Pages 주소)은 미리 채워서 설정을 묻지 않게 함
- 드문 경우(새 레포)는 별도 파일로 분리해 본문을 짧게 유지
- 위험한 동작(`--force`, 확인 없는 push, 다른 과제 삭제)은 "하지 말 것"에 명시
