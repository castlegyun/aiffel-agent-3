# 해설 노트 만들기 (코드 / 텍스트)

코드나 배운 글을 초보자용 노트로 바꿔 `06-code-explain-notes/notes/<날짜-주제>/index.html` 에 저장한다.
사용자는 코딩 초보다. 영어 용어는 한글 발음을 괄호로 붙인다. 예: import(임포트).

설명 규칙은 `06-code-explain-notes/CLAUDE.md` 8개를 따른다. 작업 전에 읽는다.

## 입력: 종류를 직접 고른다

첫 낱말이 종류다. 코드인지 텍스트인지 스스로 판단하지 않는다.

| 부르는 법 | 종류 | 입력 |
|---|---|---|
| `/explain-code 코드 game.js` | 코드 | 파일 경로 |
| `/explain-code 코드` | 코드 | 채팅에 붙여 넣은 코드 |
| `/explain-code 텍스트 notes.txt` | 텍스트 | 파일 경로 |
| `/explain-code 텍스트` | 텍스트 | 채팅에 붙여 넣은 글 |

- 종류가 없으면 "코드와 텍스트 중 어느 쪽인가요?"를 묻고 기다린다.
- 파일이 없으면 만들지 말고 경로를 다시 묻는다. 붙여 넣은 내용이 없으면 무엇을 해설할지 묻는다.
- 코드가 60줄을 넘거나 글이 20문단을 넘으면 해설할 범위를 묻는다. 코드의 언어가 불분명하면 묻는다.

## 공통 절차

1. **내용 읽기**: 전체와 (코드면) 언어를 확인한다.
2. **주제와 폴더 이름**: 주제는 짧은 한글 낱말 1~3개. 폴더는 `06-code-explain-notes/notes/YYYY-MM-DD-주제/`. 같은 이름이 있으면 `-2`를 붙인다.
3. **내용 작성**: 설명 규칙 1~8을 적용한다.
   - 제목, 결론 한 줄
   - 새 용어: `용어 = 한 줄 정의`. **한글로 쓴 개념어만** 넣는다 (영어 철자 없음). 비유 없이 실제 동작이나 뜻으로 쓴다.
   - 단어장: `단어(한글 발음): 뜻`. **영어 단어, 약어, 명령어, 도구 이름**은 모두 여기에 넣는다. 정의가 필요하면 뜻 칸에 쓴다.
   - 같은 낱말을 새 용어와 단어장에 둘 다 쓰지 않는다. 한글 개념어(함수)는 새 용어에 정의하고, 그 영어(function)는 단어장에 발음과 함께 둔다. 어느 쪽인지 애매하면 새 용어에는 한글 개념어만 남긴다.
   - 추측은 "추측:", 전제가 있으면 "(파이썬 기준)"처럼 적는다. 모르면 모른다고 쓴다.
   - **그림 판단**: 그림이 글보다 도움이 되는지 먼저 정하고, 되면 아래 표에서 종류를 고른다. 고른 이유(또는 필요 없는 이유)를 한 줄로 쓴다. 무조건 그림을 만들지 않는다.

     | 설명 내용의 성격 | 그림 종류 |
     |---|---|
     | 순서대로 진행, 조건에 따라 갈라짐 | 플로우차트 |
     | 개념끼리 포함·연결 관계 | 개념 관계도 |
     | 데이터가 어디서 어디로 이동 | 데이터 이동 구조도 |
     | 한 줄씩 실행되며 값이 바뀜 (코드) | 단계별 실행 과정 |
     | 파일·함수가 어떻게 나뉘었는지 | 코드 구조도 |
     | 한두 줄짜리 단순 개념 | 그림 필요 없음 |
4. **HTML 만들기**: 종류에 맞는 틀을 복사해 `{{...}}` 자리를 채운다. 틀의 CSS와 JS는 바꾸지 않는다. 본문에 `<`, `>`, `&` 는 `&lt;`, `&gt;`, `&amp;` 로 바꾼다.
5. **보관함 목록 갱신**: `06-code-explain-notes/notes/index.json` 을 읽어(없으면 `[]`) 맨 앞에 추가한다.
   `{"id": "폴더이름", "title": "제목", "summary": "결론 한 줄", "date": "YYYY-MM-DD", "type": "code 또는 text"}`
6. **확인**: 만든 파일에 `{{` 가 남아 있지 않은지, `index.json` 이 올바른 JSON인지 확인한다.
7. **알리기**: 만든 파일 경로 하나와 결론 한 줄만 알린다. 커밋과 푸시는 사용자가 요청할 때만 한다.

## 코드 노트: `templates/note.html`

탭은 흐름 / 자세히 / 단어장.

| 자리 | 채울 것 |
|---|---|
| `{{TITLE}}` `{{SUMMARY}}` | 제목, 결론 한 줄 (코드가 무엇을 하는지) |
| `{{TERMS}}` | `<li><strong>용어</strong> = 정의</li>` 여러 줄 |
| `{{FLOW_ROWS}}` | 코드 줄마다 `<tr><td class="n">1</td><td><code>코드</code></td><td>전체에서 하는 역할(한 줄 이내)</td></tr>` |
| `{{DETAIL_ROWS}}` | 같은 형식. 설명은 명령어가 실제로 어떻게 작동하는지, 값이 어떻게 바뀌는지. 설치 방법은 뺀다. |
| `{{WORDS}}` | `<li><strong>단어</strong>(발음): 뜻</li>` 여러 줄 |

코드 들여쓰기는 `&nbsp;` 로 유지한다.

## 텍스트 노트: `templates/note-text.html`

탭은 요약 / 풀어쓰기 / 단어장. 원문에 없는 내용을 지어내지 않는다. 원문이 틀렸거나 모호해 보이면 "추측:"으로 표시하고 사용자에게 묻는다.

| 자리 | 채울 것 |
|---|---|
| `{{TITLE}}` `{{SUMMARY}}` | 제목, 결론 한 줄 (이 글이 말하는 핵심) |
| `{{TERMS}}` | 코드 노트와 같음 |
| `{{POINTS}}` | 핵심 3~5줄. `<li>핵심 한 문장</li>` |
| `{{PARAGRAPH_ROWS}}` | 원문을 문단(또는 의미 단위)으로 나눠 `<tr><td class="n">1</td><td>원문</td><td>쉽게 풀어쓴 설명</td></tr>`. 풀어쓰기는 원리를 쉬운 말로 먼저, 용어 이름은 나중에. 비유는 쓰지 않는다. |
| `{{WORDS}}` | 코드 노트와 같음 |

## 그림 탭 (두 틀 공통)

`{{VISUAL}}` 자리는 아래 둘을 `<p>`로 채운다. 그림이 필요 없으면 종류 줄을 `그림 종류: 없음`, 이유 줄을 `필요 없는 이유:`로 쓴다.

```html
    <p class="visual-kind"><strong>그림 종류:</strong> 단계별 실행 과정</p>
    <p class="visual-reason"><strong>고른 이유:</strong> 한 줄</p>
    <p class="visual-note">그림 자체는 다음 단계에서 연결됩니다.</p>
```
