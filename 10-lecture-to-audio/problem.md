# 문제 정의서: 교안을 듣기용 음성으로 바꾸기

> 상태: 확정(2026-11-17). 결과는 [results.md](results.md).

## 도메인
AI 부트캠프(모두의연구소 아이펠 AI 에이전트 과정) 수강생의 복습.
수업 교안은 LMS에서 내보낸 마크다운 노트북(ipynb)이다. 글 사이에 표, 코드 블록, 영어 모델 이름(CLIP, SigLIP 2 등), 소수점 숫자(0.005 등), 그림이 섞여 있다.

## 지금의 문제
- 교안은 눈으로만 복습할 수 있다. 걷거나 기차를 타고 이동하는 시간에는 복습을 못 한다.
- 교안 글을 그대로 음성 엔진에 넣으면(기준선), 알아듣기 어려운 자리가 생긴다.
  - 영어 이름을 글자 하나씩 읽거나 엉뚱하게 읽는다 (예: `SigLIP 2`, `google/siglip2-base-patch16-224`).
  - 소수점·기호를 이상하게 읽거나 건너뛴다 (예: `0.005~0.015`, `53%`).
  - 표는 칸 글자를 줄줄이 이어 읽어서 어느 값이 어느 줄의 값인지 알 수 없다.
- 지금은 이 문제를 풀 방법이 없다. 그래서 이동 중에는 복습을 하지 않는다.

## 개선 가설
음성으로 만들기 **전에** AI가 교안을 "듣기용 대본"으로 바꾸면 잘못 읽히는 자리가 크게 줄어든다.
- 코드 → 무엇을 하는 코드인지 한 문장 + 꼭 필요한 이름만 소리 나는 대로
- 영어·숫자·기호 → 소리 나는 대로 한글로 (예: SigLIP 2 → 시그립 투, 0.005 → 영 점 영영오)
- 표·그림 → 읽지 않는다 (들어서 알아듣기 어렵고, 교안을 다시 볼 때 보면 된다)

넣는 자리: 교안 → **[AI: 듣기용 대본 변환]** → 음성 엔진 → 음성 파일.
덧붙여, 만든 음성을 음성 인식으로 다시 받아 적어 "이렇게 읽혀야 한다" 목록과 맞춰 보면 사람이 다 듣지 않아도 잘못 읽힌 자리를 찾을 수 있다.

## 대상 사용자
나 자신(이동 시간이 긴 수강생). 1월부터 아산↔영등포를 기차로 통학할 예정이라, 오가는 길에 교안을 눈으로 보는 것보다 듣는 쪽이 더 편하다. 소리로 들으면 집중에도 도움이 될 것으로 기대한다(내 판단, 이번 시험에서 재지는 않았다). 영어 낱말을 소리로 들었을 때 바로 알아듣기 어려운 입문자에게 특히 도움이 된다.

## 성공 기준
시험 자료: 교안 「내 업무 어디에 AI를 넣을까?」의 구간 20개, 그 안의 어려운 자리 40곳(`answer_key.json`). 정답은 모델을 돌리기 전에 확정했다(2026-11-17).
표와 그림은 듣기용 대본에서 읽지 않기로 해서(사용자 결정) 시험 구간에서 뺐다.
실제로 돌린 시험은 그중 6구간이다(s004, s096, s098, s105, s110, s143 — 어려운 곳 17곳). 과제 범위에 맞춰 "적당한 크기로 시험"하기로 했다(사용자 결정 2026-11-17). 나머지 14구간은 정답만 적어 두었다.

| # | 잰 것 | 기준 |
|---|---|---|
| 1 | 잘못 읽힌 자리 수 (사람이 듣고 판정) | 듣기용 대본이 그대로 읽기보다 8할 이상 줄인다 |
| 2 | 대본 변환에서 빠지거나 지어낸 내용 | 0건 |
| 3 | 자동 점검(음성 인식) 판정과 사람 판정의 일치 | 9할 이상 |
| 4 | 어려운 자리가 없는 구간(대조군 8개) | 대본으로 바꿔도 나빠지지 않는다 |

## 모델 선정 (확인 날짜 2026-11-17, 공식 페이지 기준)
후보는 크기만 다른 것 대신 **실행 위치와 성격이 다른 것**으로 골랐다. 지금 쓰는 방법(교안 그대로 읽기)도 기준선으로 넣었다.

| 역할 | 고른 것 | 성격 | 고른 이유 |
|---|---|---|---|
| 입력 | 교안 그대로 / 듣기용 대본 | 기준선 / AI 변환 | 개선 가설을 그대로 비교한다 |
| 대본 변환 | Claude Code (언어 모델) | 텍스트 생성 | API 키 없이 쓸 수 있다. 변환 결과를 파일로 저장해 누구나 같은 대본에서 다시 돌릴 수 있다 |
| 음성 1 | Windows 내장 `Microsoft Heami Desktop` | 이미 쓰는 도구, 오프라인 | 설치가 필요 없다. 지금 바로 쓸 수 있는 방법이라 기준으로 삼기 좋다. 단 내가 들어 보니 듣기 힘든 편이라(사용자 평가) 실제로 쓰기엔 다른 대안이 필요했다 |
| 음성 2 | Piper `ko_KR-kss-medium` (`piper-tts` 1.8.0) | 오픈 모델, 내 컴퓨터 CPU | 공식 한국어 목소리가 있고 Windows 설치 파일이 있다. 한국어 전용 형태소 분석기·GPU가 필요 없다. 코드 GPL-3.0, 모델 MIT(학습 데이터 KSS는 비상업) |
| 음성 3 | Google Cloud TTS `ko-KR-Neural2-C` | 외부 API(무료 한도 안) | Heami 대안으로 한 달 무료 한도가 넉넉해서 골랐다. 목소리 4개(Chirp 3 HD 2개, Neural2 2개)를 직접 들어 보고 가장 나은 것으로 골랐다. 한국어 목소리 목록은 공식 문서 기준. 한 달 무료 한도는 가격 페이지에 Neural2 100만 자로 나와 있다 |
| 음성 4 | ElevenLabs `eleven_v4`, 목소리 Brian | 외부 유료 API | 품질 비교용. 무료 한도(월 1만 자) 때문에 시험 6구간 대본(1,467자)만 넣었다 |
| 자동 점검 | faster-whisper 1.2.1, `large-v3`, CPU int8 | 음성 인식 | 한국어를 지원하고 6GB 그래픽카드 없이 CPU로도 돈다(36초 음성 → 약 45초) |

뺀 후보와 이유
- XTTS-v2: 한국어는 되지만 PyTorch를 따로 깔아야 하고, 공식 테스트가 Linux뿐이라 Windows에서 돌지 확인하지 못했다. 가중치는 비상업 라이선스.
- MeloTTS: 공식 문서가 Windows는 Docker를 권하고, 고정된 옛 버전 의존성이 많다.
- Kokoro: 공식 목소리 목록에 한국어가 없다.
