소리를 글자로 바꾸지 않고 한 모델에 넣으면, 사라지던 단서는 남고 중간 확인은 어려워진다

글·그림·소리는 각각 숫자 목록(임베딩)으로 바뀌어 한 모델 안에서 함께 쓰인다. 음성 인식은 사람이 쓴 규칙 → 확률 → 신경망(CTC·Whisper)으로 발전해 현장 녹음의 오류가 크게 줄었다. 실제로 고를 때는 모델 크기만 보지 말고 한국어 학습 여부, 녹음 방식, 파일 형식, 실행 도구를 따로 확인해야 한다.

새 용어 30개 (눌러서 펼치기)
  • 모달리티 = 정보가 담긴 형식. 글, 이미지, 음성, 영상, 표, 센서값이 각각 하나의 모달리티다
  • 멀티모달 AI = 형식이 다른 정보(글·그림·소리 등)를 함께 받아 질문에 답하거나 작업을 하는 AI
  • 인코더 = 입력(그림 한 장, 문장 하나)을 받아 숫자 목록으로 바꿔 주는 부분. 그림용과 글용이 따로 있을 수 있다
  • 임베딩 = 인코더가 내놓은 숫자 목록. 원문 기준으로 그림 하나, 문장 하나가 각각 숫자 몇백 개가 된다
  • 임베딩 공간 = 임베딩이 놓이는 좌표계. 숫자 목록 하나가 이 공간의 점 하나다
  • 표현 = 임베딩과 같은 것을 가리키는 말. 원본을 그대로 복사한 것이 아니라, 쓸 만한 특징만 숫자로 줄여 담은 것
  • 대조 학습 = 짝이 맞는 그림·설명은 임베딩 공간에서 가깝게, 짝이 안 맞는 쌍은 멀게 놓이도록 학습하는 방법
  • 정렬 ① (형식 맞추기) = 서로 다른 형식(그림·글·소리)을 같은 공간에서 거리로 비교할 수 있게 맞추는 일
  • 정렬 ② (시간 정렬) = 녹음 하나 안에서 어느 소리 구간이 어느 글자에 해당하는지 짝짓는 일. ①과 이름만 같고 하는 일이 다르다
  • 연결형 = 이미지·음성 전용 인코더가 뽑은 정보를 언어 모델에 넘기는 설계
  • 공유 임베딩형 = 여러 모달리티를 같은 임베딩 공간에 놓아 서로 비교하는 설계
  • 네이티브 멀티모달형 = 글·이미지·음성을 한 모델의 입력·출력 흐름 안에서 처음부터 함께 다루도록 만든 설계
  • 전사 = 말소리를 글로 받아쓰는 일, 또는 받아쓴 글
  • 스펙트로그램 = 짧은 구간마다 높이(주파수)별 소리 세기를 재서, 가로=시간·세로=주파수로 펼친 그림
  • 음향 모델 = 소리 조각을 받아 어떤 발음일지 확률을 내는 부분
  • 발음 사전 = 단어마다 발음 기호 열을 사람이 적어 둔 목록. 옛 음성 인식기는 여기 없는 단어를 인식하지 못했다
  • 언어 모델 = 어떤 단어 다음에 어떤 단어가 올 법한지 아는 부분. 대량의 글로 만든다
  • 디코더 (옛 음성 인식기) = 음향 모델·발음 사전·언어 모델 셋을 합쳐 가장 그럴듯한 문장을 찾는 부분. 이 노트에서 디코더는 이 뜻으로만 쓴다
  • 빈칸 기호 = CTC에서 출력에 하나 더한 기호. 소리 조각마다 글자 대신 이 기호를 낼 수 있다
  • 맥락 길이 = 모델이 한 번에 받아 볼 수 있는 입력의 길이. 토큰 수로 센다
  • 가중치 ① (모델 파일) = 학습으로 정해진, 모델 안의 숫자들. 내려받는 모델 파일이 바로 이 숫자 묶음이다
  • 가중치 ② (CTC 문단) = 옛 방식에서 긴 발음과 짧은 발음을 얼마나 중하게 볼지 사람이 정하던 조절값. ①과 다른 뜻이다
  • 글자 오류율 = 받아쓴 결과에서 틀린 글자의 비율. 한국어는 띄어쓰기 때문에 단어가 아니라 글자 단위로 센다
  • 강건함 = 녹음 환경(마이크 거리, 소음, 전화)이 달라져도 성능을 유지하는 성질
  • 8비트로 줄이기 (양자화) = 계산에 쓰는 숫자의 정밀도를 낮춰 메모리와 시간을 아끼는 것. 정확도가 조금 떨어질 수 있다
  • 실시간(스트리밍) 받아쓰기 = 말하는 도중에 글자가 나오는 방식. 30초씩 통째로 처리하는 방식은 말이 끝나야 결과가 나온다
  • 옴니 모델 = 글·소리·이미지·영상을 어떤 조합으로든 입력으로 받는 모델
  • 선형 투영 = 입력 숫자들에 정해진 곱셈·덧셈을 한 번 적용해, 모델이 다루는 형태의 숫자 목록으로 바꾸는 계산 (원문에 정의가 없어 일반적인 뜻을 적었다)
  • 추론 엔진 = 모델 파일을 메모리에 올리고, 입력을 바꾸고, 그래픽카드에서 계산시키고, 나온 숫자를 다시 글자로 되돌리는 프로그램
  • 중간 산출물 = 일을 단계로 나눴을 때 단계 사이에 남는 결과(예: 받아쓴 글). 이게 남아 있어야 어느 단계에서 틀렸는지 짚을 수 있다
  • 먼저 볼 것은 입력 개수가 아니라, 판단에 필요한 단서가 글·그림·소리 중 어디에 있는가예요.
  • 형식이 다른 입력은 인코더가 각각 숫자 목록(임베딩)으로 바꾸고, 같은 공간에서 거리로 비교해요. 다만 가깝다고 같은 것은 아니에요.
  • 음성 인식의 오래된 벽은 어느 소리 구간이 어느 글자인지 모른다(시간 정렬)는 것이었어요. CTC는 가능한 짝짓기의 확률을 모두 더해서 이 문제를 없앴고, Whisper는 68만 시간 자료로 회의·전화 녹음의 오류를 대략 절반으로 줄였어요.
  • 받아쓰기 모델을 고를 때는 크기뿐 아니라 한국어로 학습했는지, 글자 단위 오류율, 마이크 위치, 파일 형식(MLX·GGUF), 실행 도구가 그 입력을 받는지를 따로 확인해요.
  • 한 모델에 소리째 맡기면 억양·침묵 같은 단서가 남지만, 중간 산출물이 없어서 어디서 틀렸는지 짚기 어려워요. 근거를 되짚을 일이면 나누고, 실시간 판단이 필요하면 한 번에 맡겨요.
#원문쉽게 풀어쓰기
1보험 심사자는 사진에서 파손 부위를 확인한 뒤 수리 견적서를 읽고 상담 녹취를 듣습니다. … 이런 일을 AI에게 맡기려면 어떻게 해야 할까요?

각 자료를 잘 다루는 전문 모델을 연결하면 될까요? 아니면 하나의 모델이 보고, 듣고, 읽게 해야 할까요?		결론: 실제 업무는 이미지 하나만 보고 판단하지 않아요. 사진·문서·녹음을 함께 봐요.
1. 보험 심사: 사진(파손 부위) + 글(견적서) + 소리(상담 녹취)
2. 의료 기록: 영상(움직임) + 숫자(차트) + 소리(말투)
3. 교육: 손글씨(그림) + 목소리 + 화면 녹화
그래서 이 글의 질문은? 자료마다 잘하는 모델을 따로 두고 이어 붙일지, 모델 하나가 전부 받게 할지예요. 글 끝(33행)에서 이 질문에 답해요.
2기존의 음성 대화 시스템은 보통 세 모델을 연결했습니다. 첫 번째가 말을 글자로 옮기면, 두 번째가 그 글을 읽고 답을 만들고, 세 번째가 답을 소리 내어 읽었습니다. 최신 구조는 음성을 받는 일과 말로 답하는 일을 하나의 모델 안에서 처리해 … 여기서 중요한 변화는 도구의 개수가 아닙니다. 글자로 옮길 때 사라지던 말투나 소리도 AI가 함께 다룰 수 있게 되었다는 점입니다.결론: 바뀐 것은 모델 개수가 아니라, 말투·소리 같은 정보가 중간에 사라지지 않게 된 점이에요.
예전 방식 (모델 3개):
1. 받아쓰기 모델: 말소리 → 글자
2. 언어 모델: 글자를 읽고 답(글자)을 만듦
3. 읽어 주기 모델: 답(글자) → 말소리
무엇이 사라졌나? 1번에서 글자만 남기 때문에, 말투나 소리 같은 정보는 2번 모델에 전달되지 않아요(구체적인 예는 12행).
최신 방식: 소리를 받는 일과 말로 답하는 일을 한 모델 안에서 해요. 중간에 글자로 바꾸는 단계에 덜 의존하니까 그 정보가 남아요.
3고객 상담 요약은 텍스트 전사만으로 시작할 수 있지만, 감정·침묵·말 끊김이 품질 지표라면 음성 단서가 필요합니다. … 자료가 많다고 무조건 좋은 것은 아닙니다. 판단에 필요한 단서가 글에 있는지, 사진에 있는지, 소리에 있는지가 중요합니다.결론: 자료를 많이 넣는 게 목표가 아니에요. 판단 근거가 어느 형식에 들어 있는지부터 따져요.
1. 상담 요약: 받아쓴 글만으로 시작할 수 있어요. 하지만 감정·침묵·말 끊김이 품질 기준이면 소리가 필요해요.
2. 설비 이상 진단: 작업자 메모보다 설비 소리, 계기판 사진, 경고등 영상이 더 중요한 증거일 수 있어요.
3. 발표 피드백: 발표문으로 논리는 볼 수 있지만, 시선·속도·머뭇거림은 영상·소리에만 있어요.
왜 중요한가? 필요 없는 형식까지 넣으면 비용과 개인정보 부담만 늘어요(4행 표 참고).
4멀티모달 AI는 글과 그림, 소리처럼 형식이 다른 정보를 함께 활용해 질문에 답하거나 작업을 수행하는 AI입니다.

“모달리티 (modality)”는 정보가 담긴 형식을 뜻합니다. … 이 업무의 핵심 증거는 어느 모달리티에 있는가 / 모달리티를 합치면 정확도가 오르는가, 책임만 커지는가 / 한 모델에 맡길 일인가, 전문 모델을 조합할 일인가 / 출력은 사람이 검증 가능한 형태인가		결론: 오늘의 한 문장 — 멀티모달 AI는 형식이 다른 정보를 함께 써서 답하거나 일하는 AI예요.
모델을 고를 때 “이미지를 넣을 수 있나?”만 묻지 말고 네 가지를 물어요.
1. 핵심 증거가 어느 형식에 있나? → 글로 요약하면 놓치는 단서가 생기니까요.
2. 형식을 합치면 정확도가 오르나, 부담만 느나? → 입력이 늘면 비용·개인정보·검증 부담도 늘어요.
3. 한 모델에 맡길까, 전문 모델을 조합할까? → 원문: 통합 모델은 맥락 연결에, 전문 모델은 측정·추적에 강한 경우가 있어요.
4. 사람이 결과를 검증할 수 있나? → 그림·소리 근거가 들어가면 틀린 이유를 설명하기도 복잡해져요.
5비전 언어 모델 (VLM, Vision-Language Model)은 이미지와 언어를 함께 다루는 모델입니다. 이미지와 글을 연결하는 대표적인 방법으로 대조 학습 (contrastive learning)이 있습니다. 짝이 맞는 이미지와 설명은 가깝게, 맞지 않는 쌍은 멀게 놓도록 학습하는 방식입니다. … 이 방법을 대규모로 적용한 모델이 CLIP입니다. 오픈AI가 2021년에 공개했는데, 인터넷에서 이미지와 그 설명글 쌍을 4억 개 모아 "어느 설명이 어느 그림에 붙는가"를 맞히도록 학습시켰습니다.결론: 그림과 글을 잇는 대표 방법은 대조 학습이고, 이걸 크게 해 본 모델이 CLIP이에요.
대조 학습이 하는 일:
1. 그림과 그 그림의 설명글을 한 쌍으로 준비해요. (CLIP은 인터넷에서 4억 쌍)
2. 그림도 숫자 목록으로, 설명글도 숫자 목록으로 바꿔요.
3. 짝이 맞는 쌍(개 사진 + 개 설명)은 거리가 가까워지게, 짝이 안 맞는 쌍(개 사진 + 고양이 설명)은 멀어지게 모델을 고쳐요.
4. 이걸 아주 많이 반복해요.
그래서 무엇이 좋아지나? 원문: 그림에 붙은 자연어 설명으로 학습했기 때문에, 무엇으로 분류할지를 자연어 문장으로 알려 줄 수 있어요.
6인코더는 입력을 받아 숫자 목록으로 바꿔 주는 부분입니다. 그림을 넣으면 숫자 몇백 개가 나오고, 문장을 넣어도 숫자 몇백 개가 나옵니다. 그렇게 나온 숫자 목록을 임베딩이라고 부르고, 임베딩이 놓이는 좌표계를 임베딩 공간이라고 부릅니다. … 두 인코더는 따로 있지만, 그 결과는 서로 비교할 수 있는 공간에 놓입니다.결론: 그림용 인코더와 글용 인코더는 따로지만, 둘이 내놓은 숫자 목록은 같은 좌표계에 놓여서 서로 비교할 수 있어요.
1. 개 사진 → 그림 인코더 → 숫자 몇백 개 (임베딩)
2. “a photo of a dog” → 글 인코더 → 숫자 몇백 개 (임베딩)
3. 숫자 목록 하나 = 좌표계의 점 하나예요. 두 점 사이 거리를 계산할 수 있어요.
4. 학습이 잘 됐으면 1과 2의 점이 가까이 있어요.
그래서? 그림으로 문장을 찾거나, 문장으로 그림을 찾을 수 있어요. 둘 다 “가장 가까운 점 찾기”로 바뀌니까요.
(“몇백 개”는 원문의 표현이에요.)
7이미지 → 먼저 설명문으로 번역 → LLM이 설명문을 읽고 답함 … 하지만 2026년의 멀티모달 AI가 모두 이미지를 설명문으로 바꾸는 것은 아닙니다.
이미지 조각 / 음성 조각 / 텍스트 토큰 → 각 모달리티를 모델이 다룰 수 있는 표현으로 바꿈 → 공유 맥락 또는 공유 의미 공간에서 함께 추론 → 텍스트·음성·이미지 등 필요한 출력으로 변환

여기서 “표현 (representation)”은 원본을 그대로 복사한 것이 아닙니다. … 업무에 쓸 수 있는 특징을 숫자 벡터로 압축합니다.		결론: 그림을 반드시 설명글로 바꿔야 AI가 이해하는 건 아니에요. 숫자 목록(표현)으로 바꿔 바로 함께 계산할 수도 있어요.
길 A (설명글 거치기): 그림 → 설명글 → 언어 모델이 읽고 답. 실제로 이렇게 도는 제품도 있어요.
길 B (숫자로 바로):
1. 그림 조각, 소리 조각, 글 토큰을 받아요.
2. 각각을 모델이 다룰 수 있는 숫자 목록(표현)으로 바꿔요.
3. 그 숫자들을 한곳에 모아 함께 계산해요.
4. 필요한 출력(글·소리·그림)으로 바꿔 내보내요.
표현은 무엇을 담나? 픽셀이나 소리 파형을 그대로 담지 않아요. 그림이면 쓸 만한 특징, 소리면 말한 내용·억양·속도·배경음 같은 단서를 숫자로 줄여 담아요.
8핵심은 그 공간에서 “가깝다”는 말이 단순히 비슷해 보인다는 느낌이 아니라, 측정 가능한 거리라는 점입니다. … 학습할 때는 본 적 없는 이미지를 넣어도, 그 이미지가 “빨간 자동차”라는 문장과 “파란 하늘”이라는 문장 사이에서 전자에 더 가깝게 놓입니다. … 서로 다른 형식의 정보를 비교할 수 있도록 맞추는 이 과정을 “정렬”이라고 부릅니다.결론: “가깝다”는 느낌이 아니라 계산한 거리예요. 그래서 처음 보는 그림도 문장과 비교할 수 있어요. 이렇게 형식이 다른 것을 비교할 수 있게 맞추는 일이 정렬 ①이에요.
1. 모델은 두 숫자 목록 사이의 거리를 숫자로 계산해요.
2. 학습은 짝이 맞는 그림·문장의 거리가 가장 가까워지도록 모델을 고쳐요.
3. 학습이 끝난 뒤 처음 보는 빨간 자동차 사진을 넣어도, “빨간 자동차” 문장 쪽이 “파란 하늘” 문장보다 가까이 놓여요.
4. 원문은 “소리·영상도 같은 공간에 놓인다고 가정하면” 글 없이 “이 사진과 비슷한 녹음”도 찾을 수 있다고 해요. 가정이라고 밝힌 부분이에요.
(이 정렬은 뒤 17행의 정렬 ② (시간 정렬)과 다른 일이에요.)
9다만 “가깝다”가 곧 “같다”는 뜻은 아닙니다. 모델이 배운 거리는 학습 데이터의 통계적 관계이므로, 그 업무에서 진짜로 중요한 차이를 항상 잡아내지는 못합니다. 따라서 거리가 가깝게 나왔다는 이유만으로 업무에서도 같은 것으로 취급해서는 안 됩니다. … 회의에서 중요한 것은 “모든 자료가 같은 문서 형식인가”가 아니라, 서로 다른 자료가 같은 질문에 답하는 데 도움이 되는가입니다.결론: 거리가 가깝게 나왔다고 업무에서 같은 것으로 취급하면 안 돼요.
1. 모델이 배운 거리는 학습 자료에서 얻은 통계적 관계예요.
2. 그래서 내 업무에서 진짜로 중요한 차이를 항상 잡아내지는 못해요.
3. 결국 확인할 것은 “형식을 똑같이 맞췄나”가 아니라 “이 자료들이 내 질문에 답하는 데 실제로 도움이 되나”예요.
(원문은 이 부분을 부서별 보고서를 회의 안건 양식으로 맞추는 일에 빗대 설명해요. 이 노트에서는 빗댄 부분을 빼고 뜻만 옮겼어요.)
10| 연결형 | 이미지/음성 전용 인코더가 LLM에 정보를 넘깁니다. | 기존 언어 모델을 활용하기 좋고, 오픈소스 생태계에 많습니다. | 세부 시각·음성 단서가 언어로 옮겨지는 과정에서 사라질 수 있습니다. |
| 공유 임베딩형 | 여러 모달리티를 같은 의미 공간에 놓습니다. | 이미지-음성 검색, 텍스트-이미지 매칭처럼 교차 검색에 강합니다. | 가깝다는 것이 곧 정답은 아닙니다. |
| 네이티브 멀티모달형 | … 한 모델의 입력·출력 흐름 안에서 다룹니다. | 대화 중 화면·소리·문맥을 함께 다루기 좋습니다. | 비용, 지연시간, 안전 정책, 검증 방법이 복잡해집니다. |

네이티브 멀티모달형의 대표적인 예는 오픈AI의 GPT-4o와 구글의 Gemini입니다. … 네이티브는 모델 설계의 방향이지 전체 서비스가 하나의 파일이라는 뜻은 아닙니다.		결론: 멀티모달 모델을 만드는 설계는 크게 셋이고, 한 모델이 둘을 섞어 쓰기도 해요.
1. 연결형: 그림·소리 전용 인코더 → 언어 모델. 이미 있는 언어 모델을 쓰기 쉬워요. 대신 세부 단서가 언어로 옮겨지며 사라질 수 있어요.
2. 공유 임베딩형: 모든 형식을 같은 공간에 놓아요(5~8행의 CLIP 방식). 그림으로 소리 찾기 같은 교차 검색에 강해요. 대신 가깝다≠정답이에요.
3. 네이티브 멀티모달형: 한 모델이 처음부터 글·그림·소리를 입력·출력으로 다뤄요. 예: GPT-4o, Gemini (둘 다 상용 서비스, 가중치 비공개). 대화 중에 화면·소리를 함께 다루기 좋지만 비용·지연·안전·검증이 복잡해요.
주의: “네이티브”는 모델을 설계한 방향이에요. 실제 서비스는 안전 필터, 도구 호출 같은 부품이 함께 돌아가요.
11좋은 멀티모달 질문은 “이 사진 설명해줘”에서 끝나지 않습니다. “판단 기준”, “근거 위치”, “불확실한 부분”, “추가로 필요한 입력”을 함께 요구해야 합니다. 그래야 모델이 본 것과 추정한 것을 분리해 검토할 수 있습니다.결론: 그림을 넣고 질문할 때는 답과 함께 근거를 따로 달라고 해야 사람이 검토할 수 있어요.
원문 예: 현장 설비 사진
1. 글로 옮기면 사라지는 단서: 녹슨 위치, 주변 배선, 계기판 상태
2. 좋은 질문: “위험 징후를 위치별로 설명해 주세요.”
3. 함께 요구할 것: 판단 기준, 근거 위치, 확실하지 않은 부분, 더 필요한 입력
4. 사람이 마지막에 볼 것: 실제 설비 규정과 맞는가
왜? 이렇게 나눠 받아야 모델이 실제로 본 것과 짐작한 것을 구분할 수 있어요.
12음성 인식 (STT, Speech-to-Text): 말을 글자로 바꿉니다. / 음성 합성 (TTS, Text-to-Speech): 글자를 말소리로 바꿉니다.
옛 질문: 말을 얼마나 정확히 받아썼는가? / 새 질문: 말소리 안의 어떤 단서가 업무 판단에 필요했는가?

상담에서 “네, 알겠습니다”라는 문장은 텍스트만 보면 동의처럼 보입니다. 그러나 긴 침묵 뒤에 나온 낮은 목소리라면 불만, 불안, 포기 신호일 수 있습니다.		결론: 받아쓰기가 정확해도, 받아쓴 글에는 남지 않는 단서가 있어요.
1. 말 → 글자 = 음성 인식(STT). 글자 → 말 = 음성 합성(TTS).
2. 예전에는 “얼마나 정확히 받아썼나”만 물었어요.
3. 이제는 “소리 안의 어떤 단서가 판단에 필요했나”도 물어요.
예가 왜 필요한가? “네, 알겠습니다”는 글자로는 동의예요. 하지만 긴 침묵 뒤 낮은 목소리였다면 불만이나 포기일 수 있어요. 이 차이는 받아쓴 글에 남지 않아요. 회의에서도 누가 말했는지, 말을 끊었는지, 어떤 단어 앞에서 머뭇거렸는지가 판단 단서일 수 있어요.
13| 전사 | 발화 내용을 텍스트로 바꿉니다. | 회의록, 상담 요약, 의료 문진 초안 | 억양·감정·침묵이 사라집니다. |
| 음향 단서 | 속도, 높낮이, 강세, 배경음, 화자 구분을 봅니다. | 콜 품질, 발표 피드백, 현장 이상음 감지 | 감정 추정은 문화·상황에 따라 틀릴 수 있습니다. |
| 네이티브 대화 | 음성을 입력·출력으로 직접 다룹니다. | 실시간 안내, 화면 공유 상담, 현장 보조 | 잘못 말한 답이 즉시 행동으로 이어질 수 있습니다. |		결론: 소리를 다루는 방법은 셋이고, 볼 수 있는 것과 위험이 서로 달라요.
1. 전사: 말한 내용만 글로 남겨요. 회의록·상담 요약에 써요. 억양·감정·침묵은 사라져요.
2. 음향 단서: 속도, 높낮이, 강세, 배경음, 누가 말했는지를 봐요. 통화 품질·발표 피드백·설비 이상음 감지에 써요. 감정 추정은 문화·상황에 따라 틀릴 수 있어요.
3. 네이티브 대화: 소리를 바로 받고 소리로 바로 답해요. 실시간 안내에 써요. 잘못 말한 답이 곧바로 행동으로 이어질 수 있어요.
원문: 2025년에 나온 네이티브 음성 대화 모델들은 톤·억양·비언어 발성(말이 아닌 소리)·배경 말소리 무시·화면·비디오 이해까지 함께 다뤄요.
14같은 사람이 "안녕하세요"를 두 번 말하면, 그 두 녹음의 파형은 한 번도 같지 않습니다. … 소리는 연속해서 흐르지만, 글은 글자 단위로 나뉩니다. 음성 인식에서는 어느 소리 구간에 어느 글자가 대응하는지 알아내야 합니다. 처음에는 사람이 만든 규칙으로 맞췄고, 이후에는 확률을 이용했으며, 나중에는 모델이 직접 학습하게 되었습니다.결론: 음성 인식이 어려운 이유는 둘이에요. 같은 말도 소리가 매번 다르고, 소리는 끊김 없이 이어지는데 글자는 하나씩 떨어져 있어요.
1. 같은 “안녕하세요”도 속도·목 상태·주변 소음 때문에 파형이 매번 달라요. 그런데 원하는 답은 늘 같은 다섯 글자예요.
2. 소리는 이어진 흐름이라, 어디서 “안”이 끝나고 “녕”이 시작하는지 표시가 없어요.
3. 그래서 어느 소리 구간이 어느 글자인지 짝지어야 해요.
그래서 어떻게 풀어 왔나? 사람이 쓴 규칙 → 확률 → 모델이 직접 학습. 16~22행이 이 순서를 따라가요. (15행은 그 전에 소리를 어떻게 펼쳐 보는지예요.)
15짧은 구간마다 어떤 높이의 소리가 얼마나 강한지를 재서 가로축을 시간, 세로축을 주파수로 놓고 그림처럼 펼치는 것입니다. 이것을 스펙트로그램이라고 부릅니다.

… 성대가 만든 웅웅거림이 입과 목이라는 관을 지나면서 특정 높이가 강조되는데, 그 강조되는 자리의 배치가 모음마다 다릅니다. … 지금 쓰는 모델들도 이 방식을 그대로 씁니다. 오디오를 스펙트로그램으로 바꾼 다음 그것을 신경망에 넣습니다.		결론: 파형을 그대로 비교하기는 어려워서, 소리를 높이별 세기로 펼친 그림(스펙트로그램)으로 바꿔 봐요. 지금 모델들도 이걸 입력으로 써요.
만드는 순서:
1. 소리를 아주 짧은 구간으로 잘라요.
2. 구간마다 낮은 소리부터 높은 소리까지, 높이별로 얼마나 센지 재요.
3. 가로=시간, 세로=높이(주파수), 진하기=세기로 그려요.
왜 이게 통하나? 성대에서 나온 소리가 입과 목을 지나며 특정 높이가 강해지는데, 강해지는 자리의 배치가 모음마다 달라요. 파형에서는 안 보이던 이 차이가 스펙트로그램에서는 진한 띠의 배치로 보여요.
원문 깊이 보기: 스펙트로그램을 처음 그린 기계(1940년대 초, 벨 연구소)는 청각장애인 발음 교육용으로 알려졌지만, 실제 목적은 목소리로 사람을 식별하는 일과 암호 통신이었다고 해요(1960년 기밀 해제).
16"이런 소리면 이 글자"라는 규칙을 사람이 계속 적어 넣어야 했는데, 사람마다 다르게 말하고 같은 사람도 매번 다르게 말하니 규칙이 끝없이 늘어났습니다.

1970년대에 방향이 바뀝니다. 규칙을 적지 말고 확률로 다루자. … 같은 구조에서도 전문가가 값을 정할 때와 데이터로 학습할 때의 성능은 크게 달랐습니다.		결론: 1970년대에 “사람이 규칙을 쓰는 것”에서 “데이터로 확률을 배우는 것”으로 바뀌었어요.
1. 초기 장치는 숫자 열 개, 단어 몇 개만 알아들었어요.
2. 단어를 늘리려니 “이런 소리면 이 글자” 규칙을 사람이 계속 추가해야 했어요. 사람마다, 매번 소리가 달라서 규칙이 끝없이 늘었어요.
3. 그래서 “이 소리가 났을 때 이 글자일 확률”을 데이터에서 배우게 했어요.
왜 이쪽으로 갔나? 원문: 같은 구조에서도 값을 전문가가 정할 때와 데이터로 학습할 때 성능이 크게 달랐고, 이후 음성 인식은 데이터로 학습하는 쪽으로 발전했어요.
17확률을 이용해도 해결해야 할 문제가 있었습니다. 소리의 길이와 글자의 길이가 안 맞습니다.

"안녕하세요"를 느리게 말한 녹음은 3초이고 빠르게 말한 녹음은 1초입니다. 그런데 정답은 둘 다 다섯 글자입니다. … 이 문제를 시간 정렬이라고 부릅니다. … 여기서는 하나의 소리 안에서 어느 구간이 어느 글자에 해당하는지를 맞추는 것이라 성격이 다릅니다.		결론: 확률을 써도 남은 벽이 정렬 ② (시간 정렬)이에요. 소리 길이는 매번 다른데 글자 수는 같아서, 어느 조각이 어느 글자인지 모르는 문제예요.
1. 느린 “안녕하세요” = 3초, 빠른 “안녕하세요” = 1초. 글자는 둘 다 5개.
2. 소리를 잘게 잘라 앞에서부터 글자와 하나씩 짝지으면 처음부터 어긋나서 전부 틀려요. 3초짜리도 1초짜리도 마찬가지예요.
3. 맞게 짝지으려면 “어느 조각이 어느 글자인지”를 알아야 하는데, 그게 바로 우리가 모르는 거예요.
8행의 정렬 ①과 무엇이 다른가? ①은 그림·글처럼 서로 다른 형식을 같은 공간에 맞추는 일이에요. ②는 녹음 하나 안에서 시간 구간과 글자를 짝짓는 일이에요.
원문: 이후 연구들은 늘였다 줄여 맞춰 보기도 하고, 숨은 상태를 두고 확률로 짐작하기도 했어요.

문제 1. 사전에 없는 단어는 못 알아들었어요. 영어 표준 발음 사전에는 사람이 적은 발음 13만 5천 개가 있지만, 신제품 이름·사내 약어·사람 이름은 누군가 새로 적어 넣어야 했어요.
문제 2. 필요한 소리 조합에 비해 예제가 모자랐어요. 발음 기호는 마흔 개 남짓이지만 앞뒤 발음까지 구분하면 조합 수가 급격히 늘어요. 2만 단어 과제에서 필요한 조합 약 55,000개 중 학습 자료에 나온 건 18,500개 → 3분의 2는 예제가 없었어요. 비슷한 조합끼리 묶어 메웠는데, 그 기준(질문 202개)도 음성학자가 직접 만들었어요.
문제 3. 새 언어로 옮기려면 네 부품을 전부 다시 만들어야 했어요. 원문은 한국어가 오래 뒤처진 구조적 이유를 여기서 찾아요.
192012년에 딥러닝이 이 분야에 들어옵니다. 오류가 27.4%에서 18.5%로, 상대적으로 33% 줄었습니다. … 그런데 바뀐 것은 네 가지 구성요소 중 음향 모델 하나뿐이었습니다. … 한 부분만 바꿔도 오류가 3분의 1 줄었다면, 소리에서 글자까지 신경망이 직접 처리하게 하면 어떨까요?결론: 2012년, 네 부품 중 음향 모델 하나만 신경망으로 바꿨는데 오류가 3분의 1 줄었어요. 그래서 “전부 신경망으로 하면?”이라는 질문이 나왔어요.
1. 바뀐 것: 음향 모델 → 신경망
2. 그대로인 것: 발음 사전, 묶어 둔 조합, 언어 모델, 디코더
3. 결과: 오류 27.4% → 18.5%
“상대적으로 33%”의 계산: 줄어든 양 27.4 − 18.5 = 8.9. 원래 값에 대한 비율 8.9 ÷ 27.4 ≈ 0.325. 원문은 이걸 약 33%(약 3분의 1)라고 써요. (오류율 숫자가 33 줄었다는 뜻이 아니에요.)
20신경망으로 소리에서 글자로 바로 가고 싶은데, 학습을 시키려면 "이 소리 조각이 이 글자"라는 짝을 미리 알려 줘야 했습니다. … 핵심은 어느 정렬이 정답인지 하나를 고르는 대신, 가능한 정렬의 확률을 모두 더하는 것입니다.

출력에 "빈칸"이라는 기호를 하나 추가하면, 같은 정답 문장에 대응하는 소리 조각 배열이 여러 가지 생깁니다. … 이 방법을 CTC 라고 부릅니다.

깊이 보기: 안 안 _ 녕 녕, _ 안 _ _ 녕, 안 _ 녕 녕 _ … 경우의 수가 엄청나게 많아 보이지만, 앞에서부터 차곡차곡 누적하는 방식으로 효율적으로 계산됩니다.		결론: CTC는 “정답 짝짓기 하나”를 알 필요를 없앴어요. 가능한 짝짓기를 전부 정답으로 치고 그 확률을 더해요. (2006년 제안, 신경망이 커진 뒤 본격적으로 쓰임)
1. 소리를 조각(프레임)으로 잘라요. 예: 5조각.
2. 모델은 조각마다 글자 하나 또는 빈칸 기호(_)를 내요.
3. 규칙: 바로 이어 반복된 글자는 하나로 합치고, 빈칸을 지워요. (원문 문장은 순서를 따로 말하지 않아요. 이 순서는 CTC 원논문을 따른 것이에요. 그래서 빈칸을 사이에 둔 안 _ 안은 “안안”이 돼요.)
4. 그러면 안 안 _ 녕 녕, _ 안 _ _ 녕, 안 _ 녕 녕 _이 모두 “안녕”이 돼요.
5. 이렇게 “안녕”이 되는 모든 배열의 확률을 더한 값을 “안녕”의 확률로 보고, 이 값이 커지도록 학습해요.
그래서 무엇이 풀렸나? 어느 조각이 어느 글자인지 미리 정해 줄 필요가 없어졌어요. 원문: 학습의 목표가 발음 길이나 나누는 위치가 아니라 글자가 나오는 순서에만 달려 있어서, 긴 발음·짧은 발음의 가중치 ②를 사람이 조절할 필요도 없어졌어요.
옛 부품이 한 번에 사라진 건 아니에요(원문): 18행의 옛 인식기는 소리 → 발음 기호 → 단어 순서로 갔어요. CTC 계열이 소리에서 글자를 바로 내게 되면서 발음 사전이 없어졌어요. 언어 모델이 모델 안으로 들어온 건 그보다 한참 뒤예요.
(경우의 수는 많지만 앞에서부터 누적해 효율적으로 계산한다고만 원문에 있고, 계산법 자체는 다루지 않아요.)
21음성 모델을 학습시키려면 녹음과 함께 누군가 듣고 받아쓴 글이 필요합니다. … 세상의 7천여 개 언어 대부분에는 그만한 자료가 없습니다.

아기는 전사본을 보고 말을 배우지 않습니다. 그냥 듣습니다.

1. 문제: 학습에는 녹음 + 사람이 받아쓴 글이 필요해요. 만들기 비싸고, 쓸 만하려면 수천 시간이 필요한데 7천여 개 언어 대부분엔 그만큼 없어요.
2. 1단계: 받아쓴 글 없는 녹음만으로 소리의 구조를 먼저 배워요.
3. 2단계: 마지막에 받아쓴 녹음을 조금만 써서 받아쓰기를 가르쳐요.
4. 결과(원문): 받아쓴 녹음 1시간만으로, 예전에 100시간을 써서 내던 성능을 넘겼어요.

Whisper가 한 일:
1. 특정 시험 자료에 맞추지 않고, 인터넷의 다양한 음성+자막 68만 시간으로 학습해요.

3. 구조: 소리를 30초씩 잘라 → 스펙트로그램 → 트랜스포머.
표 읽기(오류율, 낮을수록 좋음): 감소율 = (이전 − 새) ÷ 이전. 예: 헤드셋 회의 (37.0 − 16.9) ÷ 37.0 ≈ 54.3%. 평균 줄은 원 논문 비교표 14줄 전체의 평균이에요. 이 줄의 55.2%는 위 공식에 29.3과 12.8을 넣은 값(약 56.3%)과 달라요. 원문은 이유를 말하지 않아요. 추측: 줄마다 감소율을 먼저 구한 뒤 그 감소율들의 평균을 냈기 때문이에요.
녹음 환경이 달라져도 성능을 지키는 성질을 강건함이라고 해요. 가중치 ①을 내려받아 내 컴퓨터에서 돌릴 수 있고, 오늘 실습에 쓰는 모델이에요.
23같은 모델이고 같은 회의인데, 각자 헤드셋을 쓴 녹음은 16.9이고 회의실에 마이크 하나 놓고 녹음한 것은 36.4입니다. 마이크가 멀어진 것만으로 오류가 두 배 이상 납니다. … 같은 새 모델을 쓰고도 마이크를 헤드셋으로 바꾸는 것만으로 36.4가 16.9까지 내려갑니다.결론: 모델만큼 녹음 방식도 오류를 크게 바꿔요. 같은 Whisper로 마이크만 헤드셋으로 바꿔도 오류가 절반 아래로 내려가요.
1. 모델을 바꾼 효과(회의실 마이크): 67.6 → 36.4. 원문은 이걸 가장 큰 효과라고 해요. 줄어든 양(31.2)으로 보면 가장 크지만, 22행의 비율(46.2%)로 보면 세 줄 중 가장 작아요.
2. 마이크를 바꾼 효과(새 모델 그대로): 36.4 → 16.9.
왜 마이크 하나가 나쁜가? 원문 사진 설명: 말하는 사람마다 마이크와의 거리가 다르고, 둘이 동시에 말하고, 뒤쪽 대화가 함께 들어와요. 각자 헤드셋을 쓰면 이 셋이 한꺼번에 사라져요.

그래서? “한국어 정확도 97%” 같은 광고를 보면 무엇을 기준으로 셌는지부터 확인해요.

지금 설치할 필요는 없지만 알아 둘 이유 셋:
1. 엔진마다 넣을 수 있는 입력이 달라요(31행).
2. 노트북에서 되던 걸 회사 서버에 그대로 올리면 열 명만 접속해도 느려져요. 시험은 간편한 도구로, 실제 운영은 다른 도구로 옮길 계획이 필요해요.
3. “초당 몇 토큰” 같은 속도 숫자는 어느 엔진으로 쟀는지부터 봐요. 같은 모델도 두세 배씩 차이 나요.
33첫째, 텍스트로 바꿀 때 사라지던 단서를 활용할 수 있습니다. … "네, 알겠습니다"를 긴 침묵 뒤에 낮은 목소리로 말했다는 사실을, 글자로 옮긴 뒤에는 물어볼 수 없지만 소리째로 넘기면 물어볼 수 있습니다.

둘째, 오류가 어느 단계에서 생겼는지 확인하기 어려워집니다. … 받아쓰기가 “제안”을 “제한”으로 옮겨 놓아도 중간 산출물이 남아 있으면 잡아낼 수 있습니다. 한 모델이 소리를 듣고 곧바로 결론을 말하면 그 중간이 없습니다.

… 회의록처럼 나중에 근거를 되짚어야 하는 일이라면 나눠 두는 편이 낫고, 실시간으로 상황을 파악해야 하는 일이라면 한 번에 받는 편이 낫습니다.		결론 (1행 질문의 답): 한 모델에 소리째 맡기면 단서가 남는 대신 중간 확인이 사라져요. 어느 쪽이 나은지는 “나중에 근거를 되짚어야 하나”로 정해요.
얻는 것: 소리를 글자로 바꾸지 않으니 억양·침묵이 남아요. “네, 알겠습니다”를 긴 침묵 뒤 낮은 목소리로 했는지, 소리째 넘기면 모델에게 물어볼 수 있어요.
잃는 것:
1. 나눠 두면: 소리 → 받아쓴 글(중간 산출물) → 요약. 받아쓰기가 “제안”을 “제한”으로 잘못 적어도, 받아쓴 글을 보면 어디서 틀렸는지 찾을 수 있어요.
2. 한 모델이면: 소리 → 바로 결론. 중간에 남는 글이 없어서, 틀린 결론이 어느 단계에서 나왔는지 짚기 어려워요.
그래서 어떻게 고르나?
- 회의록처럼 나중에 근거를 되짚어야 하는 일 → 나눠 두기
- 실시간으로 상황을 파악해야 하는 일 → 한 모델에 한 번에
  • modality(모달리티): 정보가 담긴 형식(글·이미지·음성 등)
  • multimodal(멀티모달): 여러 형식을 함께 다루는
  • VLM(브이엘엠): Vision-Language Model(비전 랭귀지 모델). 이미지와 언어를 함께 다루는 모델
  • contrastive learning(컨트래스티브 러닝): 대조 학습
  • CLIP(클립): 오픈AI가 2021년 공개한 모델. 그림-설명글 4억 쌍으로 대조 학습했다
  • encoder(인코더): 입력을 숫자 목록으로 바꾸는 부분
  • embedding(임베딩): 인코더가 내놓은 숫자 목록
  • representation(레프리젠테이션): 표현
  • vector(벡터): 숫자를 한 줄로 늘어놓은 것. 원문의 “숫자 벡터”는 임베딩을 가리킨다
  • token(토큰): 글을 모델이 다루는 작은 조각으로 나눈 단위
  • LLM(엘엘엠): Large Language Model(라지 랭귀지 모델). 큰 언어 모델
  • native(네이티브): 처음부터 그렇게 만든
  • GPT-4o(지피티 포 오): 오픈AI의 네이티브 멀티모달 모델. o는 omni(옴니)
  • Gemini(제미나이): 구글의 네이티브 멀티모달 모델
  • omni(옴니): 라틴어에서 온 말로 “모든 것”
  • open source(오픈 소스): 만든 코드를 공개해 누구나 쓰고 고칠 수 있게 한 것
  • STT(에스티티): Speech-to-Text(스피치 투 텍스트). 음성 인식
  • TTS(티티에스): Text-to-Speech(텍스트 투 스피치). 음성 합성
  • ASR(에이에스알): Automatic Speech Recognition(오토매틱 스피치 레코그니션). 자동 음성 인식
  • spectrogram(스펙트로그램): 가로=시간, 세로=주파수로 소리 세기를 펼친 그림
  • frame(프레임): 소리를 잘게 자른 한 조각
  • CTC(시티시): Connectionist Temporal Classification(커넥셔니스트 템포럴 클래시피케이션). 2006년 제안. 가능한 정렬의 확률을 모두 더하는 학습 방법
  • wav2vec 2.0(웨이브투벡 투 점 영): 받아쓴 글 없는 녹음으로 먼저 소리 구조를 배우는 방식
  • label(라벨): 정답 표시. 여기서는 녹음에 붙은 받아쓴 글
  • benchmark(벤치마크): 성능을 비교하려고 정해 둔 시험 자료
  • Whisper(위스퍼): 오픈AI가 2022년 공개한 음성 인식 모델. 68만 시간으로 학습, 가중치 공개
  • transformer(트랜스포머): Whisper가 쓰는 신경망 구조. 「두 길이 트랜스포머에서 합류하다」 노트 참고
  • parameter(파라미터): 모델 안 숫자(가중치 ①)의 개수를 말할 때 쓰는 말
  • tiny / base / small / medium / large(타이니 / 베이스 / 스몰 / 미디엄 / 라지): Whisper의 크기 이름. 뒤로 갈수록 크다
  • large-v3(라지 브이쓰리): Whisper large 크기의 v3 판. v는 version(버전, 판)
  • turbo(터보): large-v3를 빠르게 만든 판
  • bit(비트): 0 또는 1 하나를 담는 가장 작은 저장 단위. 8비트 = 8개
  • MB / GB(메가바이트 / 기가바이트): 저장 크기 단위. 1GB는 약 1,000MB
  • RAM(램): 컴퓨터가 계산하는 동안 쓰는 메모리
  • GPU(지피유): 그래픽카드의 계산 장치. 모델 계산을 빠르게 한다
  • CPU(씨피유): 컴퓨터의 기본 계산 장치
  • VRAM(브이램): 그래픽카드가 가진 자기 메모리. 모델이 여기 다 들어가야 빨라진다
  • Apple Silicon(애플 실리콘): 애플이 만든 M시리즈 칩
  • Colab(코랩): 브라우저에서 원격 GPU를 쓰는 서비스
  • session(세션): 접속해서 쓰고 있는 한 번의 연결
  • faster-whisper(패스터 위스퍼): Whisper 모델을 더 빠르게 실행하는 도구. 소리 파일 읽는 기능이 들어 있다
  • ffmpeg(에프에프엠펙): 음성 도구 대부분이 먼저 깔아야 하는 별도 프로그램(원문 기준)
  • streaming(스트리밍): 말하는 도중에 결과가 계속 나오는 방식
  • Qwen3-ASR(큐웬 쓰리 에이에스알): 2026년 1월 공개된 음성 인식 모델(0.6B / 1.7B)
  • license(라이선스): 써도 되는 조건. 예: Apache 2.0(아파치 투 점 영), OpenMDW(오픈엠디더블유)
  • GGUF(지지유에프): 가중치·토크나이저·부가 정보를 한 파일에 담은 모델 파일 형식. llama.cpp 계열이 바로 읽는다
  • MLX(엠엘엑스): 애플이 만든 M시리즈 전용 머신러닝 틀, 그리고 그 틀용 모델 형식
  • tokenizer(토크나이저): 글을 토큰으로 나누는 도구
  • metadata(메타데이터): 파일에 대한 부가 정보
  • Metal(메탈): 애플 기기의 GPU를 쓰게 해 주는 애플의 기술
  • llama.cpp(라마 씨피피): C++로 만든 로컬 모델 실행 도구
  • Ollama / LM Studio / llamafile(올라마 / 엘엠 스튜디오 / 라마파일): llama.cpp 계열을 쓰는 간편한 로컬 실행 도구들
  • Gemma 4(젬마 포): 구글이 가중치를 공개한 옴니 모델. 소리·영상 입력도 받는다
  • B (12B, E4B)(비): Billion(빌리언), 10억. 12B = 파라미터 120억 개
  • 128K(백이십팔 케이): K는 천 단위를 나타내는 표시. 원문은 정확한 토큰 수를 밝히지 않는다
  • model card(모델 카드): 모델 배포 페이지에 붙은 설명서
  • inference(인퍼런스): 추론. 학습이 끝난 모델로 답을 내는 일
  • vLLM / SGLang / LMDeploy(브이엘엘엠 / 에스지랭 / 엘엠디플로이): 여러 사람의 요청을 함께 처리하는 서버용 추론 엔진
  • C++(씨플플): 프로그래밍 언어 이름
