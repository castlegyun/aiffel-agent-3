AI는 표·단백질·날씨·로봇까지 다루지만, 결과가 맞는지는 분야마다 따로 확인해야 한다

AI는 글·그림 밖에서도 표·단백질 서열·날씨 자료를 받아 예측하고 로봇 동작을 만든다. 어느 분야든 “무엇을 받고, 무엇을 내놓고, 맞는지 어떻게 확인하나”로 읽고, 높은 점수나 그럴듯한 결과만으로 업무·현장에 바로 쓸 수는 없다.

새 용어 18개 (눌러서 펼치기)
  • 분류 = 표의 각 행이 어느 부류(예: 불량/정상, 악성/악성 아님)에 속하는지 가르는 일
  • 기준선 = 새 모델과 비교하려고 같은 자료로 함께 돌리는 기존 방법. 이 실습에서는 랜덤 포레스트와 그래디언트 부스팅
  • 훈련 자료 = 모델에 정답과 함께 예시로 주는 행. 랜덤 포레스트·그래디언트 부스팅은 이 행으로 학습하고, TabICL은 이 행을 예측할 때 참고하는 맥락으로 쓴다
  • 시험 자료 = 점수를 매길 때까지 정답을 감춰 두는 행. 모든 모델에 같은 것을 쓴다
  • 정확도 = 시험 행 가운데 정답을 맞힌 비율. 맞힌 행 수 ÷ 전체 시험 행 수
  • 양성(평가에서) = 우리가 찾아내려는 쪽. 이 실습에서는 악성이 양성이다. (덧붙인 설명) 의학에서 말하는 ‘양성 종양(악성이 아님)’과 다른 뜻이다
  • 음성(평가에서) = 찾아내려는 쪽이 아닌 사례. 이 실습에서는 악성 아님이 음성이다. ‘목소리’라는 뜻이 아니다
  • 문턱 = 모델이 매긴 점수 몇 점부터 양성으로 판정할지 정한 선
  • 사전학습 = 사용자가 쓰기 전에 모델이 미리 많은 자료로 끝내 둔 학습
  • 기반 모델 = 원문의 ‘표를 위한 기반 모델’: 여러 표를 다루는 법을 미리 학습해 두고, 사용자가 건넨 예시 행과 정답을 참고해 새 행의 답을 내는 모델
  • 가중치 = 학습으로 정해진 모델 안의 숫자들. 이 글에서는 그 숫자를 담아 내려받는 파일을 가리킨다
  • 서열 = 단백질을 이루는 아미노산이 어떤 순서로 이어져 있는지 글자로 적은 것
  • 단백질 구조 예측 = 서열에서 사슬이 접힌 입체 모양(원자 위치)을 추정하는 일
  • 단백질 설계 = 원하는 모양을 먼저 정하고, 그 모양으로 접힐 법한 새 서열을 찾는 일
  • 수치예보 = 현재 대기 상태에서 출발해 물리 방정식을 계산으로 풀어 날씨를 예보하는 방식
  • 재분석 자료 = 실제 관측과 수치모델을 결합해 과거 대기 상태를 일관된 형태로 정리한 자료
  • 월드 모델 = 지금 장면과 하려는 행동을 받아 다음 장면(환경이 어떻게 달라질지)을 예측하는 모델
  • 이용 조건 = 코드·가중치·자료를 어디까지 써도 되는지 정한 규칙. 셋이 서로 다를 수 있다
  • AI가 받는 자료는 분야마다 달라요: 표(측정값), 단백질(아미노산 서열), 날씨(지구 여러 지점의 대기 상태), 로봇(카메라 영상+작업 지시). 내놓는 결과도 점수·구조 파일·다음 날씨·팔의 동작으로 달라요.
  • 표 모델을 비교할 때는 시험 자료를 하나로 고정하고, 기준선(랜덤 포레스트·그래디언트 부스팅)과 새 모델(TabICL)을 함께 돌려, 정확도와 AUC를 둘 다 봐요.
  • 20행 실습에서 그래디언트 부스팅은 표를 보지 않고 한 가지 답만 내서 AUC 0.5인데도 정확도는 0.6257이었어요. 찾으려는 사례를 하나도 못 찾아도 정확도는 절반을 넘을 수 있어요.
  • 단백질·날씨·로봇·월드 모델은 계산 결과가 나온 뒤에도 실제 실험, 같은 조건의 비교, 안전한 작업 완료, 현실에서도 통하는지 확인이 남아요.
  • 업무에 쓰기 전에는 ① 실행할 수 있나(장치·메모리·가중치 받는 절차) ② 이용 조건이 맞나(코드·가중치·자료를 따로 읽기) ③ 업무 자료로도 점수가 좋나(문턱에서의 비용까지) 순서로 확인해요.
#원문쉽게 풀어쓰기
1물류 담당자가 출고 기록을 열어 놓고 묻습니다. “다음 달에는 얼마나 들여놔야 할까요?” 품질 담당자는 부품 검사표를 보며 불량 가능성이 큰 것을 먼저 골라내고 싶어 합니다. 두 사람 모두 숫자가 적힌 표를 갖고 있지만, 원하는 답은 다릅니다. 한 사람은 앞으로의 수량을, 다른 사람은 부품별 위험을 알고 싶습니다.결론: 같은 ‘숫자 표’라도 원하는 답이 다르면 해야 할 일이 달라요.
1. 물류 담당자: 출고 기록 → 다음 달 들여놓을 수량(앞으로의 숫자)을 알고 싶어요.
2. 품질 담당자: 부품 검사표 → 불량 가능성이 큰 부품(부품별 위험)을 먼저 골라내고 싶어요.
왜 이 장면으로 시작하나? 강의 마지막 절(내 업무에서 시작할 수 있는 일)에서 이 두 사람에게 돌아가, 각자 어떤 실험이 필요한지 답해요. 표가 비슷해 보여도 묻는 것이 다르면 문제와 평가 방법이 달라진다는 것이 이 강의의 출발점이에요.
2AI를 쓴다고 하면 이 표를 챗봇에 올리고 설명을 부탁하는 장면부터 떠올리기 쉽습니다. 실제로는 표에서 분류 결과를 내는 모델, 시간에 따라 이어지는 숫자를 예측하는 모델이 따로 있습니다. 입력을 문장으로 바꾸지 않고 숫자와 열의 관계를 다루는 것입니다. 연구실로 가면 입력은 단백질의 아미노산 서열이 되고, 기상 분야에서는 지구 여러 지점의 날씨가 됩니다. 로봇에서는 카메라 영상과 작업 지시를 받아 다음 동작을 만들어 냅니다.결론: AI는 챗봇만이 아니에요. 분야마다 받는 자료가 다른 모델이 따로 있어요. 표 모델은 문장으로 바꾸지 않고 숫자를 그대로 받아요.
  · 표: 행마다 분류 결과를 내는 모델 / 시간에 따라 이어지는 숫자를 예측하는 모델
  · 연구실: 단백질의 아미노산 서열을 받아요.
  · 기상: 지구 여러 지점의 날씨를 받아요.
  · 로봇: 카메라 영상 + 작업 지시를 받아 다음 동작을 만들어요.
무엇이 다른가? 표를 챗봇에 올려 “설명해 줘”라고 하면 챗봇은 글로 답해요. 표 모델은 숫자와 열 사이의 관계를 직접 계산해서 행마다 답을 내요. 이 강의는 뒤쪽을 다뤄요.
3이 강의에서는 그중 업무에서 접하기 쉬운 표 데이터를 직접 다룹니다. 같은 검사표를 여러 모델에 넣고, 답을 맞힌 정도를 비교해 보겠습니다. 이어서 단백질 연구, 기상 예보, 로봇에서는 무엇을 넣고 무엇을 얻는지 살펴봅니다. 모든 모델을 설치하기보다는, 한 실험을 끝까지 해 본 경험으로 다른 분야의 결과도 읽어 보려는 것입니다.

핵심 한 문장: AI는 글과 그림뿐 아니라 표, 단백질 서열, 날씨 자료를 다루고 로봇의 동작을 만드는 데에도 쓰입니다.

학습 목표: 표 예측, 단백질 연구, 기상 예보, 로봇에서 AI가 받는 자료와 내놓는 결과를 설명할 수 있습니다. / 공개된 표 데이터로 모델을 비교하고, 정확도와 AUC를 읽을 수 있습니다. / 모델을 업무에 쓰기 전에 실행 환경, 평가 방법, 이용 조건을 확인할 수 있습니다.

실습은 구글 계정과 브라우저만 있으면 시작할 수 있습니다. 무료 Colab의 CPU를 사용하므로 GPU를 배정받지 못해도 같은 순서로 진행합니다. 개인 업무 자료는 준비하지 않아도 됩니다. 공개 예제 데이터로 파일 저장까지 마치고, 자기 업무에 옮길 때 달라지는 점은 실습 뒤에 살펴봅니다.		결론: 표 실험 하나를 끝까지 해 보고, 그 경험으로 다른 분야의 결과를 읽어요.
1. 표 데이터: 같은 검사표를 여러 모델에 넣고 맞힌 정도를 비교해요. (직접 실습)
2. 단백질·기상·로봇: 무엇을 넣고 무엇을 얻는지만 살펴봐요. (설치·실행은 안 해요)
학습 목표 세 가지 = 이 노트의 뼈대예요.
  · ① 분야별로 받는 자료와 내놓는 결과 설명하기
  · ② 정확도와 AUC 읽기
  · ③ 업무에 쓰기 전에 실행 환경·평가 방법·이용 조건 확인하기
실습 준비: 구글 계정과 브라우저만 있으면 돼요. 무료 Colab의 CPU로 돌리기 때문에 GPU를 못 받아도 같은 순서로 진행해요. 개인 업무 자료는 필요 없고 공개 예제 데이터만 써요.
4검사표의 한 행에 부품 하나의 측정값이 있고, 마지막 열에는 나중에 확인한 불량 여부가 있다고 해 보겠습니다. 이미 결과를 아는 행을 모델에 보여 주면, 모델은 측정값과 불량 사이의 관계를 배웁니다. 그다음 새 부품의 측정값을 넣어 불량 가능성을 추정합니다. 과거 출고량으로 다음 달 수량을 예상하는 것과 달리, 여기서는 각 행이 어느 부류에 속하는지를 가르는 분류를 합니다.결론: 결과를 이미 아는 행으로 관계를 배우고, 새 행이 어느 부류인지 가르는 일이 분류예요.
1. 검사표 한 행 = 부품 하나. 앞 열들은 측정값, 마지막 열은 나중에 확인한 불량 여부(정답)예요.
2. 정답이 있는 행을 모델에 보여 줘요 → 모델이 측정값과 불량 사이의 관계를 배워요.
3. 새 부품은 측정값만 넣어요 → 모델이 불량 가능성을 추정해요.
분류와 수량 예측의 차이: 출고량 예측은 “얼마나?”(숫자)에 답하고, 분류는 “어느 쪽?”(불량/정상)에 답해요. 이 강의 실습은 분류예요.
5랜덤 포레스트와 그래디언트 부스팅은 이런 표 데이터에 널리 쓰이는 방법입니다. 주어진 표로 학습한 뒤 새로운 행을 예측합니다. 표를 위한 기반 모델은 출발점이 조금 다릅니다. 미리 여러 표를 다루는 법을 학습해 두고, 사용자가 건넨 예시 행과 정답을 참고해 새 행의 답을 냅니다. 이 강의에서 쓸 TabICL이 그런 모델입니다. 사용자의 표를 보고 답한다고 해서 학습을 전혀 안 한 모델은 아닙니다. 이미 사전학습을 거쳤으며, 지금 건네는 표는 예측에 필요한 맥락으로 쓰입니다.

(그림 설명) 랜덤 포레스트는 예시 행으로 학습하고, 사전학습된 TabICL은 예시 행을 참고해 새 부품의 불량 가능성을 예측합니다. 같은 시험 자료에서 정확도를 비교하고, 불량 부품에 더 높은 점수를 주는지도 봅니다.		결론: 두 방식 모두 정답이 붙은 예시 행을 쓰지만, 쓰는 방법이 달라요.
1. 랜덤 포레스트·그래디언트 부스팅: 지금 건넨 표로 학습 → 새 행을 예측해요. 표가 바뀌면 그 표로 다시 학습해요.
2. 표를 위한 기반 모델(TabICL): 여러 표를 다루는 법을 미리 학습(사전학습)해 둬요 → 사용자가 건넨 예시 행과 정답은 참고할 맥락으로 써요 → 새 행의 답을 내요.
헷갈리기 쉬운 곳: ‘학습’이 두 가지로 나와요.
  · 사전학습 = 미리 끝내 둔 학습. TabICL은 이것을 거쳤어요.
  · 지금 건넨 표 = 예측할 때 참고하는 자료. 원문은 이것을 “맥락”이라고 불러요.
그래서 “사용자의 표를 보고 답한다”가 “학습을 전혀 안 했다”는 뜻은 아니에요.
‘훈련 자료’도 같은 구분이에요. 실습 비교표의 ‘훈련 행 수’(20행/200행)는 랜덤 포레스트·그래디언트 부스팅에게는 학습 재료이고, TabICL에게는 예측할 때 참고하는 맥락이에요.
6작은 표에서도 이런 방식이 도움이 될 수 있습니다. 그렇다고 새 모델이라는 이유만으로 먼저 고를 수는 없습니다. 랜덤 포레스트가 비슷하게 맞히면서 준비가 간단할 수도 있습니다. 우리에게 필요한 것은 같은 자료로 비교한 결과입니다. 비교할 때 함께 돌리는 기존 방법을 기준선이라고 합니다. 기준선이 있어야 새 모델을 받아 설치하는 수고에 비해 무엇이 나아졌는지 알 수 있습니다.결론: 새 모델이 더 나은지는 같은 자료로 기존 방법과 나란히 돌려 봐야 알아요. 이 기존 방법이 기준선이에요.
1. 작은 표에서도 기반 모델이 도움이 될 수 있어요.
2. 하지만 랜덤 포레스트가 비슷하게 맞히면서 준비가 더 간단할 수도 있어요.
3. 그래서 “새 모델이니까”가 아니라 비교 결과로 골라요.
왜 기준선이 필요한가? 새 모델은 받아서 설치하는 수고가 들어요. 기준선이 없으면 그 수고로 무엇이 나아졌는지 잴 수 없어요.
7비교를 시작하기 전에 표를 둘로 나눕니다. 모델에 예시로 주는 쪽은 훈련 자료이고, 결과를 확인할 때까지 정답을 감춰 두는 쪽은 시험 자료입니다. 훈련에 쓴 행으로 점수를 매기면 이미 본 문제를 다시 푼 셈이 됩니다. 또 모델마다 시험 자료가 다르면 문제 난이도가 달라져 공정하게 견주기 어렵습니다. 이번 실습에서는 시험 자료를 한 번 정해 놓고 끝까지 그대로 사용합니다.결론: 표를 둘로 나누고, 정답을 감춰 둔 쪽(시험 자료)은 한 번 정하면 끝까지 같은 것을 써요.
1. 훈련 자료: 모델에 예시로 주는 행
2. 시험 자료: 점수를 매길 때까지 정답을 감춰 두는 행
지키는 규칙 두 가지와 이유
  · ① 훈련에 쓴 행으로 채점하지 않아요 → 이미 본 문제를 다시 푸는 셈이에요. (덧붙인 설명) 그래서 점수가 실제보다 좋게 나올 수 있어요.
  · ② 모든 모델에 같은 시험 자료를 줘요 → 시험 자료가 다르면 문제 난이도가 달라져서 공정하게 견줄 수 없어요.
8점수도 하나만 보지 않겠습니다. 정확도는 전체 시험 행 가운데 정답을 맞힌 비율입니다. 쉽게 이해할 수 있지만, 불량이 드문 표에서는 불량을 하나도 찾지 못한 모델도 높은 정확도를 얻을 수 있습니다. 그래서 모델이 각 행에 매긴 점수의 순서도 살펴봅니다. 불량을 찾는 일이라면 실제 불량인 행이 정상인 행보다 대체로 높은 점수를 받아야 유용하겠지요.결론: 정확도는 맞힌 비율이라 이해하기 쉽지만, 찾으려는 사례가 드물면 속을 수 있어요.
1. 계산: 맞힌 시험 행 수 ÷ 전체 시험 행 수
2. 함정: 불량이 드문 표에서 모든 부품을 “정상”이라고만 답해도 대부분 맞아요. 불량은 하나도 못 찾았는데 정확도는 높게 나와요.
3. 그래서 하나 더 봐요: 모델이 행마다 매긴 점수의 순서. 실제 불량 행이 정상 행보다 대체로 높은 점수를 받아야 쓸모가 있어요.
이 함정이 실제로 나오는 곳: 실습의 20행 결과에서 그래디언트 부스팅이 정확도 0.6257을 받았지만 악성을 하나도 구별하지 못했어요(아래 실습 절).
9이 순서를 평가하는 지표가 ROC AUC, 줄여서 AUC입니다. 양성 사례 하나와 음성 사례 하나를 골랐을 때 양성에 더 높은 점수를 주는 정도를 나타냅니다. 동점은 절반으로 계산합니다. 1에 가까울수록 둘을 잘 구별하고, 0.5는 무작위로 순위를 매기는 수준입니다. 여기서 양성은 검사 결과가 좋다는 뜻이 아니라 우리가 찾아내려는 쪽을 가리킵니다. 실습에서는 악성인 사례를 양성으로 정합니다.결론: AUC는 찾으려는 사례(양성)에 더 높은 점수를 주는 정도예요. 1에 가까우면 잘 가르고, 0.5면 무작위로 순위를 매긴 수준이에요.
원문 설명을 단계로 풀면
1. 양성 하나와 음성 하나를 짝지어 골라요.
2. 양성의 점수가 더 높으면 1, 같으면 0.5(절반), 낮으면 0을 줘요.
3. (덧붙인 설명) 가능한 모든 짝에서 이 값을 평균 내면 AUC가 돼요.
설명용 예 (원문에 없는 숫자): 악성 두 개의 점수 0.9·0.6, 악성 아님 두 개의 점수 0.7·0.2 → 짝 4개: (0.9 vs 0.7) 1, (0.9 vs 0.2) 1, (0.6 vs 0.7) 0, (0.6 vs 0.2) 1 → 평균 3 ÷ 4 = 0.75.
주의: ‘양성’이 두 뜻이에요.
  · 평가에서 양성 = 우리가 찾아내려는 쪽. 이 실습에서는 악성이 양성이에요.
  · 의학에서 양성(종양) = 악성이 아니라는 뜻.
실습 데이터가 유방암이라 두 뜻이 정면으로 부딪혀요. 이 노트에서 ‘양성’은 평가 뜻으로만 쓰고, 의학 뜻은 “악성 아님”이라고 써요.
10AUC가 높아도 바로 현장에 적용할 수 있는 것은 아닙니다. 실제로는 어느 점수부터 양성으로 판정할지 문턱을 정해야 합니다. 문턱을 낮추면 더 많은 사례를 검사 대상으로 고르지만, 정상 사례도 함께 늘 수 있습니다. AUC는 여러 문턱에서의 구별 능력을 요약하고, 정확도는 실제로 나눈 답이 얼마나 맞았는지 보여 줍니다. 두 값을 함께 보는 이유입니다. 사람이 추가 검사를 할 수 있는 양과 놓쳤을 때의 피해는 이 숫자만으로 결정되지 않습니다.결론: 모델은 점수만 줘요. 현장에서 답(양성/음성)을 내려면 문턱을 정해야 하고, 문턱은 숫자가 아니라 업무 사정이 정해요.
1. “몇 점부터 양성으로 판정할까?” = 문턱. 사람이 정해요.
2. 문턱을 낮추면 → 검사 대상으로 고르는 사례가 많아져요 → 정상(음성) 사례도 함께 섞여 늘 수 있어요.
3. AUC = 여러 문턱에서의 구별 능력을 요약한 값 / 정확도 = 문턱을 정해 실제로 나눈 답이 맞은 비율 → 그래서 둘을 함께 봐요.
숫자로 정해지지 않는 것: 사람이 추가 검사를 할 수 있는 양, 놓쳤을 때의 피해. 이건 업무가 정해요.
[그림] 탭의 문턱 움직여 보기에서 문턱을 옮기며 고른 수·놓친 수가 바뀌는 것을 볼 수 있어요(설명용 가상 점수).
11공개 예제에서 점수가 높게 나오는지도 확인할 가치가 있지만, 그 결과를 자기 회사의 표에 그대로 적용할 수는 없습니다. 열의 의미와 자료가 모인 과정이 다릅니다. 기반 모델이라면 공개 평가 자료가 사전학습과 겹치는지도 살펴야 합니다. 수업에서는 사용법과 비교 방법을 익히고, 실제 도입에서는 별도로 확보한 자료로 다시 평가해야 합니다.결론: 공개 예제에서 점수가 높아도, 우리 회사 표에서도 높다는 뜻은 아니에요.
그대로 옮길 수 없는 이유 세 가지
1. 열의 의미가 달라요.
2. 자료가 모인 과정이 달라요.
3. 기반 모델이라면 공개 평가 자료가 사전학습 때 이미 본 자료와 겹치는지도 살펴야 해요. (덧붙인 설명) 겹치면 이미 본 문제를 푼 셈이라 점수가 부풀 수 있어요.
그래서: 수업 = 사용법과 비교 방법 익히기 / 실제 도입 = 따로 확보한 자료로 다시 평가하기
12이제 실제 표로 비교해 보겠습니다. scikit-learn에 들어 있는 유방암 분류 예제 데이터를 사용합니다. 569개 사례마다 측정값 30개가 있고, 각 사례가 악성인지 아닌지가 정답으로 붙어 있는 공개 데이터입니다. 의료 분야에서 온 자료지만, 이 실습으로 진단 도구를 만드는 것은 아닙니다. 정답이 이미 있는 표를 빌려 모델 비교 과정을 익히겠습니다.결론: 정답이 이미 붙은 공개 표(유방암 분류 예제)를 빌려, 모델 비교 과정만 익혀요.
  · 569개 사례 × 측정값 30개 + 정답(악성인지 아닌지)
  · 의료 자료지만 진단 도구를 만드는 실습이 아니에요.

더 볼 곳: TabICL 저장소, scikit-learn 데이터 설명. 실습 노트북 코드와 비교표를 옆에 두고 읽으면, 문서의 입력 형식·평가 방법이 노트북의 어느 단계인지 찾기 쉬워요.
  • AI(에이아이): Artificial Intelligence(아티피셜 인텔리전스), 인공지능 (일반 지식)
  • LMS(엘엠에스): Learning Management System(러닝 매니지먼트 시스템). 이 강의 자료를 내보낸 학습 관리 시스템
  • Random Forest(랜덤 포레스트): 표 데이터에 널리 쓰는 방법. 주어진 표로 학습한 뒤 새 행을 예측한다. 이 실습의 기준선 1
  • Gradient Boosting(그래디언트 부스팅): 표 데이터에 널리 쓰는 방법. 판단 기준을 하나씩 세워 나간다. 이 실습의 기준선 2
  • TabICL(탭아이씨엘): 표를 위한 기반 모델. 사전학습을 거쳤고, 사용자가 건넨 예시 행과 정답을 맥락으로 참고해 새 행의 답을 낸다. 추측: 이름의 ICL은 in-context learning(인 컨텍스트 러닝)의 줄임으로 보이며, 원문에는 이름 풀이가 없다
  • ROC AUC(알오씨 에이유씨): 줄여서 AUC. 양성 하나·음성 하나를 골랐을 때 양성에 더 높은 점수를 주는 정도. 동점은 절반으로 센다. 1에 가까울수록 잘 구별하고 0.5는 무작위 순위 수준
  • scikit-learn(사이킷런): 파이썬의 머신러닝 도구 모음(일반 지식). 실습의 유방암 분류 예제 데이터가 들어 있다
  • Python(파이썬): 프로그래밍 언어 이름 (일반 지식)
  • Colab(코랩): 브라우저에서 파이썬 노트북을 실행하는 환경. 구글이 제공한다(일반 지식)
  • Notebook(노트북): 이 글에서 두 뜻으로 쓰인다. ① 코드 칸(셀)과 설명 글을 한 파일에 담아 위에서부터 실행하는 문서(실습 노트북, 예제 노트북) ② 휴대용 컴퓨터(날씨 절의 ‘개인 노트북’)
  • Cell(셀): 노트북 안의 칸 하나. 차례로 실행한다
  • Runtime(런타임): 노트북 코드가 실제로 돌아가는 실행 환경(CPU 또는 GPU를 고른다)
  • CPU(씨피유): Central Processing Unit(센트럴 프로세싱 유닛). 컴퓨터의 기본 계산 장치(일반 지식). 표 실습은 이것만으로 돌아간다
  • GPU(지피유): Graphics Processing Unit(그래픽스 프로세싱 유닛). 많은 계산을 동시에 하는 장치(일반 지식). 무료 Colab에서는 항상 배정되지는 않는다
  • T4(티포): Colab에서 고를 수 있는 GPU 종류 이름. 월드 모델 조작판 실습에서 쓴다
  • CSV(씨에스브이): Comma-Separated Values(콤마 세퍼레이티드 밸류스). 표를 쉼표로 구분해 적은 글 파일(일반 지식). 실습 비교표를 이 형식으로 저장한다
  • Package(패키지): 설치해서 쓰는 코드 묶음. TabICL도 패키지를 설치해 쓴다
  • ColabFold(콜랩폴드): 아미노산 서열을 넣으면 단백질 구조를 예측해 구조 파일을 내주는 도구
  • PDB(피디비): 구조 파일의 대표 형식. 각 원자의 좌표가 담긴다
  • pLDDT(피엘디디티): 구조 예측 결과의 각 부분을 모델이 얼마나 확신하는지 나타내는 값. 구조 그림을 이 값으로 색칠하기도 한다
  • RMSD(알엠에스디): Root Mean Square Deviation(루트 민 스퀘어 디비에이션, 이름 풀이는 일반 지식). 대응 원자 사이 거리의 제곱을 평균 내고 제곱근을 취한 값. 같은 조건이면 작을수록 두 구조가 가깝다
  • RFdiffusion(알에프디퓨전): 단백질 사슬이 지나갈 뼈대(모양)를 만드는 데 쓰는 모델
  • ProteinMPNN(프로틴엠피엔엔): 주어진 뼈대에 맞을 법한 아미노산 서열을 제안하는 모델
  • AlphaFold2 (AF2)(알파폴드 투): 구조 예측 모델. 원문 그림에서 설계한 서열의 모양을 예측하는 데 쓰였다
  • GraphCast(그래프캐스트): 과거 대기 상태와 그 뒤 상태를 학습해 다음 대기 상태를 예측하는 날씨 모델
  • ERA5(이알에이 파이브): GraphCast 학습에 쓰인 재분석 자료
  • TPU(티피유): Tensor Processing Unit(텐서 프로세싱 유닛). 구글의 AI 계산용 장치(일반 지식). GraphCast 연구는 TPU v4 한 대에서 열흘 예보를 1분 미만에 만들었다고 보고했다
  • VLA(브이엘에이): Vision(비전, 영상)·Language(랭귀지, 언어)·Action(액션, 행동)을 함께 다루는 모델
  • SmolVLA(스몰브이엘에이): VLA 분야의 공개 모델 가운데 하나. 모델 카드에 가중치 라이선스가 Apache-2.0으로 표시되어 있다
  • LeRobot(르로봇): 로봇 데이터 수집과 학습 등을 다루는 공개 도구
  • Hugging Face(허깅 페이스): AI 모델과 도구를 공개·공유하는 회사이자 사이트(일반 지식). 원문의 LeRobot 시연 출처가 ‘Hugging Face LeRobot 개발팀’이다
  • DIAMOND(다이아몬드): 게임 화면과 행동을 받아 다음 화면을 만드는 월드 모델 연구
  • Agent(에이전트): 환경 안에서 어떤 행동을 할지 고르는 쪽. DIAMOND에서는 월드 모델 속에서 게임을 한다
  • TabPFN(탭피에프엔): 가중치에 별도 이용 조건이 있는 표 모델의 예로 원문에 나온다
  • Checkpoint(체크포인트): 학습 결과(가중치)를 저장해 둔 특정 파일. 실제로 고른 체크포인트의 조건을 확인해야 한다
  • Cellpose(셀포즈): 세포 영상 모델. 학습 자료에 비상업 조건이 붙은 예로 원문에 나온다
  • License(라이선스): 코드·가중치·자료를 어디까지 써도 되는지 적은 이용 조건 문서. 저장소에는 보통 LICENSE 파일로 들어 있다
  • CC-BY-NC(씨씨 바이 엔씨): 비상업 조건. (일반 지식) 출처를 밝히면 쓸 수 있지만 상업적 이용은 안 된다. NC = Non-Commercial(논커머셜)
  • CC BY 4.0 / CC BY-SA 4.0(씨씨 바이 / 씨씨 바이 에스에이): 원문 그림 출처에 붙은 이용 조건 이름
  • Apache-2.0(아파치 투): 공개 라이선스의 한 종류. SmolVLA 가중치와 LeRobot 시연 그림에 붙어 있다
  • Model card(모델 카드): 모델의 가중치, 기반 모델, 학습 자료, 이용 조건 등을 설명하는 안내 페이지
  • Repository(리포지토리(저장소)): 코드와 문서를 모아 둔 곳. 원문의 ‘저장소’
